## Supervisor integration contract v1 — shared transaction implementation
`getSlotRuntime(State)` is the shared adapter for all owners. It reads only the active `State.S.resonance`; use `capture()` at the start of an actual gameplay action to capture an opaque slot/scene token (browser global: `CatBondResonance.captureAction()`). Pass the token on completion. The token is not a save, is not serialized and is invalid after a slot/scene change. Battle, support, exchange and postgame results require it. The engine still validates sequence and duplicate evidence. `evidence(proof, physical)` and `exchange(proof, physical)` accept a synchronous pure physical patch function receiving copies of `{resonanceExploration,coins,fish}`; the returned patch and story update are persisted together via State.save(), rolled back together if local persistence fails. Only those fields may be patched. Map adapter remains responsible for actual spatial/operation evidence and reward policy. Never use this API to simulate gameplay in production. `subscribe(fn)` notifies only after local commit; cloud backup lifecycle is owned by Chat 2. No shared-file wiring is changed in this increment. Chat 3/7 must migrate their current separate transaction implementations in coordination with Supervisor; this PR does not assert they are already integrated.
